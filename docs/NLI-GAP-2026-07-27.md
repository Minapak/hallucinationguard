# The lexical-vs-entailment gap, measured — NLI backend V1 (2026-07-27)

The V0 baseline is deliberately lexical, and its documented weakness is this benchmark's
central finding. M2 promised to put a number on the gap by running an NLI checker beside it.
This document is that number — produced by [`harness/nli_v1.py`](../harness/nli_v1.py), raw
per-item scores in [`harness/runs/`](../harness/runs/), reproducible with
[`harness/requirements.txt`](../harness/requirements.txt) (torch 2.13.0 · transformers 5.14.1,
macOS arm64, Python 3.12, Apple-silicon MPS).

**Model**: [`MoritzLaurer/mDeBERTa-v3-base-xnli-multilingual-nli-2mil7`](https://huggingface.co/MoritzLaurer/mDeBERTa-v3-base-xnli-multilingual-nli-2mil7)
(~279M params, ~560MB). Chosen over stronger English-only grounding checkers
(MiniCheck, EMNLP 2024; AlignScore, ACL 2023) because this benchmark's contract is 7 locales
including ko/ja/zh-Hans — a weaker multilingual judge beats a stronger monolingual one that
cannot read 3 of the 7. Caveat stated up front: XNLI's language list excludes Korean and
Japanese; coverage there rides on mDeBERTa's CC100 pretraining, so per-locale numbers below
are measurements, not assumptions.

**Granularity**: sentence-by-sentence on both sides (SummaC's design, Laban et al., TACL
2022). This was measured to matter, not assumed — see §3.

## 1. The headline number

The pair the README opens with, scored three ways:

| Metric | "Measurement collapses the state." vs "Measurement **never** collapses the state." |
|---|---|
| Bag-of-words cosine (demo) | 0.87 — "nearly identical" |
| V0 token overlap | high (only the added token differs) |
| **NLI contradiction** | **0.989** (identity control: entailment 0.958) |

The failure class the benchmark documents is real, and the entailment family closes it —
on this pair. The rest of this document is what happens beyond the clean pair.

## 2. Pattern-free misconception detection (HG120 sample, 7 locales)

The V0 forbidden-claim gate blocks all 7 misconception-asserting items in every locale —
but only because v3.1 localized hand-written patterns for each. The NLI dimension needs no
patterns. What it catches, and what it costs:

| Locale | NLI catches (of 7 wrong) | NLI false alarms (of 4 faithful) | V0 gate | Layered union |
|---|---|---|---|---|
| en | 4/7 (HG002 · 031 · 073 · 115) | 2/4 (HG005 · HG006) | 7/7 | **7/7** |
| ko | 6/7 | 1/4 (HG005) | 7/7 | **7/7** |
| ja | 4/7 | 3/4 | 7/7 | **7/7** |
| zh-Hans | 6/7 | 2/4 | 7/7 | **7/7** |
| es | 4/7 | 3/4 | 7/7 | **7/7** |
| fr | 5/7 | 2/4 | 7/7 | **7/7** |
| de | 5/7 | 1/4 (HG005) | 7/7 | **7/7** |

Readings, both directions:

- **NLI catches what patterns must be written for.** HG031 (S/Z gates interchangeable),
  HG073 (no more cryptanalysis needed), HG115 (cooling removes decoherence) are flagged at
  contradiction 0.97–0.99 with zero pattern authoring — across scripts, including ko/zh.
- **NLI misses what patterns catch.** HG039 (Grover solves NP-complete in polynomial time)
  is *never* flagged (conflict 0.03 en): complexity-class reasoning is beyond a 279M NLI
  cross-encoder. HG023 (consciousness collapses the wave function) sits just under
  threshold in en (0.46). The pattern gate catches both.
- **Neither alone suffices; the union always does.** That is the layered-gate design the
  factual-consistency literature recommends (TRUE, NAACL 2022; layering synthesis in
  docs/AUDIT-2026-07-19.md §sources) — measured here rather than cited on faith.

## 3. Granularity is load-bearing (whole-document NLI fails silently)

With the whole KB entry as a single premise, this model rated HG002's faster-than-light
answer **entailed at 0.88** and a fully correct bra-ket answer **contradicted at 0.72** —
both silently wrong. Split into sentence pairs, HG002's FTL sentences flag at 0.50–0.61
(1.00 against the KB's no-signalling sentence) and 3 of 4 HG006 sentences clear. SummaC's
"granularity mismatch" finding, reproduced on quantum-education content.

## 4. Measured residual limits (why this ships as a dimension, not a gate)

1. **Notation-dense sentences false-alarm.** HG006-en's correct bra/ket-dual sentence stays
   at conflict 0.71; verbalizing the notation was tested and made it *worse* (0.39→0.56).
   Ships as a documented model limitation, not papered over.
2. **Max-aggregation is brittle on multi-sentence KB.** On the HGX extension, answers built
   from the KB's own text (HGX01/02) and the balanced control (HGX06) still show max
   conflict 0.80–0.97: some pair of *different* KB sentences reads as contradiction to the
   model, and max-pooling amplifies every such pair. This is exactly why SummaC-ZS
   (zero-shot max/mean pooling) is outperformed by SummaC-Conv's learned aggregation in the
   original paper — the M2 remainder is calibration/aggregation, not a bigger model.
3. **Per-locale reliability varies** (§2 false-alarm column: ja/es worst at 3/4). The
   ko result (6/7 catches, 1/4 false alarms) is *better* than feared given XNLI excludes
   Korean — but it is one 20-item sample, not a license.
4. **Cost**: ~26–380ms per answer on Apple-silicon MPS after a seconds-scale model load
   (batched sentence pairs; full 20-item locale run ≈ 6s wall). CPU-only Fargate would be
   slower — one reason the production integration is shadow-only.

## 5. Where this runs in production (QuantumNative), without touching shipped clients

The deployed iOS/macOS apps compute the guard **on-device** (Swift port of v0.2.0) and the
EDU web BFF runs its own TS port; neither calls the backend guard endpoint — verified
2026-07-27 (zero references in either client codebase). The NLI dimension therefore ships
server-side as a **shadow observer**, and the shipped clients are untouched by construction:

- **Backend** (`QuantumNative_Backend/app/services/hg_nli_shadow.py`): same model, same
  sentence-pair rule, env-gated (`HG_NLI_SHADOW=1`, default off), deps optional
  (`requirements-nli.txt`), lazy-loaded, never raises, and **never writes the tier** — the
  scorer's verdict is final before the shadow runs. Result is logged and returned only as
  the additive `nli_shadow` field of `POST /api/v1/knowledge/validate`.
- **Web BFF** (`QuantumNativeEDU_Web/src/lib/hgNliShadowForward.ts`): fire-and-forget
  forward of (question, answer, KB anchor, locale) to that endpoint; no-op unless
  `HG_NLI_SHADOW_FORWARD_URL` is set; 1.5s abort; every failure swallowed. The web verdict
  path is unchanged.
- Both sides carry shadow-contract tests (backend: `tests/test_hg_nli_shadow.py`, 43-test
  suite green; web: `__tests__/hg-nli-shadow-forward.test.ts`, 32-test suite green) that
  assert the tier/response are byte-identical with the shadow off, and tier-untouched even
  when a fake checker screams contradiction.

## 6. From shadow to gate — the V2 rule, selected by measurement

The §4 limits were then attacked directly, and the result is a real gate with a
measured-zero false-block record — inside an explicitly scoped domain.

**Rule search.** Candidate aggregations were evaluated on labeled pair data (forward score,
reverse score, support) for every gate-eligible sentence across the full grid:

| Rule | False blocks (en, 8 faithful) | Catches (en, 8 wrong) |
|---|---|---|
| R1 zero-shot max (§4 baseline) | 5 | 5 |
| R2 + bidirectional confirmation (min of both directions ≥ 0.5) | 1 | 3 |
| R4 = R2 + support < 0.5 | 1 | 3 |

Bidirectional confirmation is the load-bearing step: true A-vs-not-A contradictions are
symmetric; most spurious topical ones are not. The residual false block (HG006's
notation-dense sentence) is *more* symmetric than several true catches — no threshold
separates it — which forced the second structural condition:

**Lexical-agreement exemption.** Every measured NLI false alarm sat on an answer the V0
lexical layer had *validated* (overlap ≥ 0.30); every true catch sat on a lexically
*low-confidence* answer. The gate therefore only ever applies to `aiWithLowConfidence`
answers — the two layers must independently agree something is wrong before anything is
suppressed.

**Measured locale scope.** With rule R7 (= R4 + low-confidence-only), the full grid
(16 items × 7 locales × both fixtures) shows:

| Locale | Gate false blocks | Gate catches (wrong answers) |
|---|---|---|
| en | **0** | 3 (HG031 · HG073 · HG115) |
| es | **0** | 4 (+ HG002) |
| fr | **0** | 3 |
| ko / ja / zh-Hans / de | 1–2 each (e.g. de HG005 at symmetric 0.93) | — |

So the gate ships **active for {en, es, fr}** and stays shadow for ko/ja/zh-Hans/de until
calibrated aggregation or a better multilingual model closes the gap (M2 remainder).
Per-segment rollout by measured quality — not a caveat, the standard practice.

**Where the gate now runs** (all verified end-to-end with the real model):

- **Benchmark** — `harness/nli_v1.py` (`nli_gate()`, V2-gate column, per-locale runs
  re-generated); `tests/test_nli.py` pins zero false blocks and ≥3 catches per active
  locale, and hard-off outside the scope.
- **Backend** — `HG_NLI_GATE=1` adds `nli_blocked` to `/api/v1/knowledge/validate`
  (suppression signal in the same contract shape as `blocked_claim`; the tier is still
  never rewritten). E2E smoke: wrong-en `nli_blocked=True` at conflict 0.9985; good-en
  exempt via VALIDATED; wrong-ko contradicted-but-unblocked (scope). 48-test suite green.
- **Web BFF** — `HG_NLI_GATE_URL` (default unset) makes the tutor route await the gate
  for low-confidence answers in scope and serve the safe fallback on `nli_blocked`;
  fail-open on any error. 36-test suite green.
- **iOS/macOS** — `HGNliGateService.swift` + escalation hook in `AITutorService`, behind
  `AppConfiguration.Features.enableServerNLIGate` (unconditionally `false`) with a
  QA-only UserDefaults override: the shipped binaries' behavior is structurally
  unchanged, and the next release can flip one static to activate. 8 new unit tests +
  the 6 scorer-parity tests green on the iOS 26.5 simulator; macOS build clean.
